# Workstation extra experiments — November 2026

Measurements were completed on 2026-11-04 in new experiment directories. They are separate from the reported September passes. Every linked README records commands, tool versions, conditions, limits and figures. The department A30 extra queue was cancelled; no further cluster work was performed.

**ws-amd — GEMM counters.** [Stable-state counter study](ws-amd/rocprof-stable-2026-11-04/README.md): 64 main-GEMM records cover one MNIST batch and a large W4 step in HIP/cudann, SYCL/AdaptiveCpp and OpenMP/amdclang with tiled BLAS, plus rocBLAS. The tiled kernels allocate **32 / 32 / 80 VGPRs** and **2048 / 2048 / 4096 bytes of dispatch LDS** respectively. For NN 4096³, occupancy is **45.45% / 45.00% / 16.80%**, and LDS bank-conflict fractions are **17.073% / 17.073% / 12.485%**. OpenMP launches 576 workgroups for that GEMM, versus 65,536 in HIP/SYCL; each OpenMP team therefore processes multiple tiles. Counter collection required the documented `profile_standard` power state, held through an ordinary DRM context and released afterward. Automatic power mode produced unusable zero readouts, retained in [diagnostics](ws-amd/rocprof-tiled-2026-11-04/README.md). VALU utilisation was not exposed; VALU instruction counts are reported instead. Kernel 7.3.0 and the profiling policy limit timing claims; CPU cap remained 2.8 GHz, boost off, CPU/memory binding node 0.

**ws-amd — bandwidth.** The 384 MiB, device-resident copy/scale/add/triad probe reports a triad **median 494.24 GB/s, best 496.26 GB/s** in [automatic GPU mode](ws-amd/stream-2026-11-04/README.md). Under [profile_standard](ws-amd/stream-stable-2026-11-04/README.md), the same binary reports **52.17 GB/s median**, with much lower recorded memory clocks. These are condition-specific measurements, not a cross-pass speed comparison or a hardware specification. Both modes use five warm-ups and 31 repetitions per operation, with the CPU policy unchanged.

**ws-amd — per-kernel roofline.** The [GL2 external-interface roofline](ws-amd/rocprof-stable-2026-11-04/figures/kernel-roofline.png) uses measured GL2 request bytes, mathematical GEMM work 2MNK, and matching kernel timestamps. The [72 MiB cache-resident triad calibration](ws-amd/stream-cache-stable-2026-11-04/README.md) gives **1309.92 GB/s** at that counter/time boundary; its ordinary event-timed logical-byte rate is 1152.99 GB/s. The best fresh rocBLAS calibration is **21.33 TFLOP/s** (4096³). Large NN intensities are **7.78 / 7.82 / 3.20 FLOP/byte** for tiled HIP/SYCL/OpenMP, versus **47.28** for rocBLAS. This is a cache-interface reference, not a DRAM roofline: Radeon has Infinity Cache beyond L2. Read/write counters require separate deterministic repeats because their combined request exceeds hardware slots; both durations are retained. The earlier figure combining these counters with the 384 MiB DRAM-dominated rate was rejected and quarantined.

**ws-nvidia — Compute Sanitizer.** [48-case matrix](ws-nvidia/sanitizer-2026-11-04/README.md), CUDA 12.9 / Compute Sanitizer 2025.2.1: **46 combinations are clean**. Memcheck, synccheck and initcheck are clean for all covered cases. Racecheck flags the float CUP-like vendor path: default **123 reported errors**; graph **122 errors and one warning**. Numerical parity assertions pass. The reports name cuBLAS `sgemm_32x32x32_*` kernels; a standalone one-stream cuBLAS reproduction with synchronisation after every GEMM also reports **8 errors** while checking correct outputs. This isolates the reports from cudann's stream ordering, but does not distinguish a cuBLAS defect from a tool false positive. Tiled-path cases are clean. Earlier pytest-selection failures were corrected and preserved, not counted as executed tests.

**ws-nvidia — bandwidth.** The [384 MiB STREAM-style probe](ws-nvidia/stream-2026-11-04/README.md), nvcc sm_61 / CUDA 12.9, reports triad **352.98 GB/s median, 354.25 GB/s best**; copy/scale/add medians are **339.56 / 341.78 / 349.53 GB/s**. Five warm-ups and 31 repetitions per operation were used. The GTX 1080 Ti ran with CPU and memory on guest NUMA node 1, bench mode enabled on the host and VM; GPU clocks were observed rather than locked.

**ws-nvidia — delimited Nsight Systems.** [Six traces and timelines](ws-nvidia/nsys-epoch-2026-11-04/README.md), N=8192, B=256, one two-epoch call after warm-up, profile off/on for CUDA, DPC++ and clang18 OpenMP. With the internal profiler off, whole-call times are **37.72 / 73.37 / 112.73 ms** and target GPU busy unions **21.50 / 23.57 / 35.65 ms**. GEMM sums are **10.33 / 11.11 / 11.10 ms**; hand-written kernel sums **3.19 / 4.49 / 16.45 ms**, with BLAS vector/reduction kernels listed separately. All captures contain **1280 kernel launches**. OpenMP records **51.14 thread-ms** in synchronisation APIs. Range wall is the explicit NVTX train interval within the CUDA-profiler capture; phase sums and host time are not additive wall partitions, and gaps in this process's GPU work do not prove that the shared physical GPU was idle. These traced times are not substituted for the independent-process timing results.

**ws-nvidia — Pascal counter limit.** [Support/access investigation](ws-nvidia/gemm-counters-2026-11-04/README.md): current Nsight Compute excludes Pascal; the obtainable 2019.5 branch supports GP10x but fails device enumeration under injection on this stack. Matched nvprof 12.9.79 lists Pascal metrics, yet both occupancy and DRAM-byte collection exit with CUDA profiling error 12. A direct legacy CUPTI event lookup returns **CUPTI_ERROR_NOT_SUPPORTED (27)** while native CUDA sees one device and succeeds. Driver 580.196.07, CUDA 12.9.79 and CUPTI API 28 are recorded. The rootless/admin-counter restriction is also recorded but is not asserted as the cause of error 27. Tools were obtained within minutes, bounded probes were retained, and no configuration change was made to enable counters. No NVIDIA counter matrix or counter-based kernel roofline is claimed.

**ws-nvidia — independent-process confirmation.** [21 fresh processes, alternating order](ws-nvidia/stat-confirm-2026-11-04/README.md): CUDA/DPC++ median steady epochs are **54.48/135.89 ms** at MNIST B=256 (**DPC++/CUDA time ratio 2.49×**) and **27.99/38.03 ms** at B=1024 (**DPC++/CUDA time ratio 1.36×**). CUP CUDA default/in-order/graph gives **4.134/3.425/1.127 ms**, a **3.67×** default-to-graph ratio. Across-process spreads range from **0.91% to 6.10%**; per-process medians and within-process steady IQRs are separate in the table. The original epochs/repeats were preserved, including CUP default 5/5 versus queue variants 5/3. Three processes are an exploratory confirmation, not a precise confidence interval.

All completed NVIDIA run blocks restored both authorised bench modes. Every AMD profiling context released its temporary power state; the GPU returned to `auto`, with CPU cap 2800000 kHz and boost 0. No pass directory, library wheel or commit was changed by these experiments.
