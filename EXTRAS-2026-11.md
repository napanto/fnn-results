# Workstation extra experiments: November 2026

Measurements were completed on 2026-11-06 in new experiment directories. They are separate from the reported passes. Every linked README records commands, tool versions, conditions, limits and figures. The ws-amd directories dated 2026-11-04 are the same studies on kernel 7.3.0, kept for the comparison between kernels. On the A30 the only extra experiment is the independent-process confirmation.

**ws-amd: GEMM counters.** [Stable-state counter study](ws-amd/rocprof-stable-2026-11-06/README.md): 64 main-GEMM records cover one MNIST batch and a large W4 step in HIP/cudann, SYCL/AdaptiveCpp and OpenMP/amdclang with tiled BLAS, plus rocBLAS. The tiled kernels allocate **32 / 32 / 80 VGPRs** and **2048 / 2048 / 3816 bytes of dispatch LDS** respectively; the separate static LDS field is 4096 bytes for OpenMP. For NN 4096³, occupancy is **57.67% / 57.50% / 36.24%**, and LDS bank-conflict fractions are **17.073% / 17.073% / 12.485%**. OpenMP launches 576 workgroups for that GEMM, versus 65,536 in HIP/SYCL; each OpenMP team therefore processes multiple tiles. Counter collection required the documented `profile_standard` power state, held through an ordinary DRM context and released afterward. Automatic power mode produced unusable zero readouts, retained in [diagnostics](ws-amd/rocprof-tiled-2026-11-06/README.md). The tool exposes VALU instruction counts; a utilisation metric was unavailable. Kernel 7.3.0 and the profiling policy limit timing claims; CPU cap remained 2.8 GHz, boost off, CPU/memory binding node 0.

**ws-amd: bandwidth.** The 384 MiB, device-resident copy/scale/add/triad probe reports a triad **median 693.17 GB/s, best 708.49 GB/s** in [automatic GPU mode](ws-amd/stream-2026-11-06/README.md). Under [profile_standard](ws-amd/stream-stable-2026-11-06/README.md), the same binary reports **696.43 GB/s median**. On kernel 7.3.0 the two values were 494.24 and 52.17 GB/s, with a 96 MHz memory clock in the profile_standard snapshot against 1249 MHz on 7.2.3. These rates describe the recorded clock and power conditions. Both modes use five warm-ups and 31 repetitions per operation, with the CPU policy unchanged.

**ws-amd: per-kernel roofline.** The [GL2 external-interface roofline](ws-amd/rocprof-stable-2026-11-06/figures/kernel-roofline.png) uses measured GL2 request bytes, mathematical GEMM work 2MNK, and matching kernel timestamps. The [72 MiB cache-resident triad calibration](ws-amd/stream-cache-stable-2026-11-06/README.md) gives **2148.21 GB/s** at that counter/time boundary; its ordinary event-timed logical-byte rate is 1765.61 GB/s. The best fresh rocBLAS calibration is **21.82 TFLOP/s** (4096³). Large NN intensities are **7.94 / 7.94 / 3.05 FLOP/byte** for tiled HIP/SYCL/OpenMP, versus **46.11** for rocBLAS. The reference describes the GL2 cache interface; Radeon has Infinity Cache beyond L2. Read/write counters require separate deterministic repeats because their combined request exceeds hardware slots; both durations are retained.

**ws-nvidia: Compute Sanitizer.** [48-case matrix](ws-nvidia/sanitizer-2026-11-04/README.md), CUDA 12.9 / Compute Sanitizer 2025.2.1: **46 combinations are clean**. Memcheck, synccheck and initcheck are clean for all covered cases. Racecheck flags the float CUP-like vendor path: default **123 reported errors**; graph **122 errors and one warning**. Numerical parity assertions pass. The reports name cuBLAS `sgemm_32x32x32_*` kernels; a standalone one-stream cuBLAS reproduction with synchronisation after every GEMM also reports **8 errors** while checking correct outputs. This isolates the reports from cudann's stream ordering, but does not distinguish a cuBLAS defect from a tool false positive. Tiled-path cases are clean. Earlier pytest-selection failures are retained in the logs; the 48-case total counts executed tests.

**ws-nvidia: bandwidth.** The [384 MiB STREAM-style probe](ws-nvidia/stream-2026-11-06/README.md), nvcc sm_61 / CUDA 12.9, reports triad **352.34 GB/s median, 353.09 GB/s best**; copy/scale/add medians are **342.78 / 343.67 / 352.05 GB/s**. Five warm-ups and 31 repetitions per operation were used. The GTX 1080 Ti ran with CPU and memory on guest NUMA node 1, bench mode enabled on the host and VM. No other process used the GPU during the run, and its clocks were observed rather than locked.

**ws-nvidia: delimited Nsight Systems.** [Six traces and timelines](ws-nvidia/nsys-epoch-2026-11-06/README.md), N=8192, B=256, one two-epoch call after warm-up, profile off/on for CUDA, DPC++ and clang18 OpenMP. With the internal profiler off, whole-call times are **35.16 / 68.97 / 99.50 ms** and target GPU busy unions **19.72 / 23.34 / 35.34 ms**. GEMM sums are **9.36 / 11.06 / 11.04 ms**; hand-written kernel sums **3.00 / 4.47 / 16.47 ms**, with BLAS vector/reduction kernels listed separately. All captures contain **1280 kernel launches**. OpenMP records **47.42 thread-ms** in synchronisation APIs. Range wall is the explicit NVTX train interval within the CUDA-profiler capture. Phase sums and host times can overlap. No other process used the GPU during the captures. Independent-process timings are reported separately below.

**ws-nvidia: Pascal counter limit.** [Support/access investigation](ws-nvidia/gemm-counters-2026-11-04/README.md): current Nsight Compute excludes Pascal; the obtainable 2019.5 branch supports GP10x but fails device enumeration under injection on this stack. Matched nvprof 12.9.79 lists Pascal metrics, yet both occupancy and DRAM-byte collection exit with CUDA profiling error 12. A direct legacy CUPTI event lookup returns **CUPTI_ERROR_NOT_SUPPORTED (27)** while native CUDA sees one device and succeeds. Driver 580.196.07, CUDA 12.9.79 and CUPTI API 28 are recorded. The rootless/admin-counter restriction is also recorded; the cause of error 27 remains unresolved. Tools were obtained within minutes, bounded probes were retained, and no configuration change was made to enable counters. The NVIDIA counter matrix and counter-based kernel roofline remain unavailable on this stack.

**ws-nvidia: independent-process confirmation.** [21 fresh processes, alternating order](ws-nvidia/stat-confirm-2026-11-06/README.md): CUDA/DPC++ median steady epochs are **53.86/134.43 ms** at MNIST B=256 (**DPC++/CUDA time ratio 2.50×**) and **27.54/36.94 ms** at B=1024 (**DPC++/CUDA time ratio 1.34×**). CUP CUDA default/in-order/graph gives **4.077/3.383/1.114 ms**, a **3.66×** default-to-graph ratio. Across-process spreads range from **0.2% to 7.9%**; per-process medians and within-process steady IQRs are separate in the table. The original epochs/repeats were preserved, including CUP default 5/5 versus queue variants 5/3. Three processes provide an exploratory repeatability check.

**hpc-a30: independent-process confirmation.** [40 fresh processes in one exclusive Slurm job, alternating order](hpc-a30/stat-confirm-2026-11-06/README.md): in-order CUDA **47.45 ms** and DPC++ **104.02 ms** at MNIST B=256, ratio **2.19×**, against 2.21× in the pass; spreads 0.3% and 3.5%. Default CUDA **43.23 ms** has a spread of 11.0%, caused by the first process.

All completed NVIDIA run blocks restored both bench modes. Every AMD profiling context released its temporary power state; the GPU returned to `auto`, with CPU cap 2800000 kHz and boost 0.
